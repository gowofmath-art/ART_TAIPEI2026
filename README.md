# ART TAIPEI 2026｜個人觀展指南

*A Personal Exhibition Guide*

一個非官方、以個人興趣出發的 ART TAIPEI 2026 精選觀展網站。從曾經喜歡的畫廊到想進一步認識的藝術家，整理十一間畫廊的展位、簡介、作品與關注緣由，作為觀展時的參考，也分享給同樣喜愛藝術的人。V1.1 保留原有五間畫廊的資料、文案與圖片，新增六間畫廊。

這份指南不是畫廊排行榜，也不是完整參展名錄。

## 畫廊精選

- **Must Visit｜必逛（6 間）**：白石畫廊、藍騎士藝術、artkake、亞洲藝術中心、貝浩登、Kaikai Kiki Gallery。
- **Interested｜有興趣（5 間）**：共感画廊、GALLERY ETHER、Gana Art、伊日藝術計劃、也趣藝廊。

十一間畫廊的欄位名稱統一為「藝術家」，沿用白石畫廊的標題字體、名單樣式及間距。藝術家超過五位時，名單可展開與收合。前端不顯示名單狀態或來源提示段落，資料中的原始備註與來源仍保留；標題統一不代表名單均已確認參展。藍騎士藝術仍為個人關注名單，共感画廊的原始名單為空，本次均未新增或更改姓名。版面支援桌面與手機，圖片保留完整構圖及原始比例；缺圖或讀取失敗時顯示佔位區域。

## 開啟網站

下載或複製整個專案，保留原有檔案結構，直接雙擊 **[index.html](index.html)**，即可使用瀏覽器開啟。請保持 JavaScript 啟用。

不需要安裝套件、啟動本機伺服器或執行建置；檔案使用相對路徑，也適合透過 GitHub Pages 發布。

## 檔案結構

以 HTML5、CSS3 與原生 JavaScript 製作的單頁靜態網站，無後端或資料庫。

```text
ART_TAIPEI2026/
├── index.html   # 頁面結構與展覽介紹
├── style.css    # 視覺設計與響應式排版
├── data.js      # 展覽資訊、畫廊資料及圖片路徑
├── app.js       # 畫廊呈現、圖片載入與名單展開／收合
├── floor-map-data.js # 依官方 PDF 核對的展位百分比座標
├── floor-map.js  # 地圖標記、縮放、拖曳與觸控
├── ART-TAIPEI-2026-Map.pdf # 使用者提供的官方完整平面圖
├── images/     # 作品與展覽圖片
└── README.md
```

## 更新內容與圖片

### 展場地圖（V1）

首頁「展場地圖 Floor Map」入口可直接跳到畫廊精選後方的地圖。完整官方 PDF 以原始比例轉成 `images/art-taipei-2026-map.webp`（5196 × 6000，約 1.2 MB），沒有裁切、重繪或移除原圖資訊，並保留官方 PDF 連結。

地圖支援按鈕與滾輪縮放、滑鼠／單指拖曳、雙指縮放、恢復全圖。地圖獲得鍵盤焦點時，可用方向鍵平移、`+` / `-` 縮放、`Home` / `0` 恢復全圖。圓點可使用 Tab 選取、Enter 前往介紹，桌面滑鼠停留可看名稱及展位。手機觸控只在地圖範圍內接管手勢，其餘頁面可正常捲動。

所有標記由既有 `data.js` 的 `galleries` 產生：`must-visit`（必逛／必去）使用 `#A64B45`；`interested`（有興趣）使用 `#34678A`。沒有另一份固定五間或十一間的畫廊名單。點擊會跳到原有卡片 `#gallery-<id>`，自動展開該分類；直接開啟深連結與瀏覽器上一頁／下一頁也沿用錨點導覽。原畫廊順序、分類、文字、圖片及名單收合方式均保留。

**後續新增標記：**

1. 在 `data.js` 的 `galleries` 新增畫廊，使用唯一 `id`，填入 `booth` 及既有 `group`。卡片資料格式照現有畫廊。
2. 若該展位已存在於 `floor-map-data.js` 的 `booths`，標記會自動出現。否則先在官方 PDF 確認展位，再加入 `展位編號: { x: 百分比, y: 百分比 }`，不可推測位置。
3. 座標基準為**整張未裁切地圖**左上角，向右為 x、向下為 y。以圖片量測時：`x = 標記中心像素 / 圖片完整寬度 × 100`，`y = 標記中心像素 / 圖片完整高度 × 100`。以本版 PDF 量測時，完整頁面是 1301.01 × 1502.36 pt。應選展位內留白處，避開文字。
4. 重新整理網頁，確認標記、分類顏色與卡片跳轉，並在放大及手機寬度下核對。缺少座標、無效座標或未支援的分類會列在地圖下方「尚待確認」，不會隨意放置。沒有展位的畫廊不會產生標記。

目前已核對 11 間：A17、A04、B27、D01、B04、D09、A02、B14、D07、D04、C13，沒有待確認的位置。`floor-map-data.js` 只保存已確認的展位座標，名稱及分類仍以 `data.js` 為準。

**更換地圖版本：**請同步更新原 PDF 與 WebP，保留整頁比例，並重新核對全部座標。網站執行時不需要 PDF 轉檔工具；維護時若有 Poppler 與 Python Pillow，可用以下步驟轉檔，完成後同步調整 `index.html` 的圖片寬高：

```text
pdftoppm -scale-to 6000 -singlefile -png ART-TAIPEI-2026-Map.pdf map-full
python -c "from PIL import Image; Image.open('map-full.png').save('images/art-taipei-2026-map.webp', quality=94, method=6)"
```

本功能使用傳統 `defer` 腳本、相對檔案路徑及本地圖片，不使用模組、fetch、CDN、後端或建置。GitHub Pages 發布時需一併包含三個既有網頁檔案、新增的兩個地圖腳本、`data.js`、全部圖片與原 PDF，保持檔名大小寫一致。

**畫廊資料**：編輯 [data.js](data.js) 的 `galleries`，即可更新名稱、展位、簡介、藝術家、關注緣由與連結。`group` 使用 `must-visit` 或 `interested` 決定分類；各分類內依資料陣列順序顯示。展期、地點與官方展覽連結則位於 `event`。

所有卡片沿用白石畫廊的共用版型：作品圖像／佔位區、編號與展位、名稱、簡短背景、藝術家、「為何關注」與官方連結。`artworks` 保留原有作品資料，不另設「重點作品」區塊；個人觀展期待保留於 `reason`，統一以「為何關注」顯示。分類數量依資料自動計算，首頁介紹、搜尋摘要及無 JavaScript 提示中的總數需同步維護。

```js
image: "images/whitestone-01.png",
```
